# 赛题二判别重设计方案（任务 4 重写）

日期：2026-07-31。状态：方案（待实施）。

## 背景与动机

新引擎（7/27 速度修复）下赛题二连跑 3 局 600s 全灭（v27~v29，均 0 分），
根因是**判别把诱饵当真目标**（每局开局 25~81s 即有诱饵误判，误识别总时长
394~600s），全队追诱饵 → kill=0、真目标漏报 accuracy=0、两机同圈 proximity
罚满。sim:state 真值实测（诊断用，不进 agent）：真目标速度 5/9/12 m/s 三档
随机，15 个诱饵恒 5 m/s；真目标无 WaitTime 停顿（A* 注入丢弃 wait 字段）。

手册（0724 更新版）确认：诱饵误判惩罚已移除（不扣分，但占用时间）；
target_type 不可靠（伪装）；判别只能靠运动学时序；decide 禁止操作 Redis。

## 量化验证（output/verify_*.py，蒙特卡洛 + 真值数据）

### A. 速度分档错误率（±50m iid 噪声，120 样本 @10Hz，带 [6.5, 13.5]）

| 真速 | OLS 入带概率 | CvFilter 入带概率 | 结论 |
|---|---|---|---|
| 5 m/s（诱饵/1/3 真目标） | **15.8%** | 12.0% | 单次判别 6~8 个就有 1 个误判真 |
| 9 m/s | 98.1% | 95.6% | 判真可靠 |
| 12 m/s | 85.9%（上限 13.5 偏紧，P90=13.75） | 93.6% | 上限放宽到 14.5 |

→ 5 m/s 档单次不可判；**二次独立验证后误报降到 15.8%² ≈ 2.5%**。

### B. Start 池归属（开局 5~35s 位置 → 最近 Start，26 真 / 18 诱）

15/18 正确（83%）。三个误判均发生在两池距离 <130m 的邻近区（如诱饵 30009
距真 Start 仅 52m）。→ 最近归属只作辅助；用双阈值 + 多帧一致才稳妥。

### C. 轨迹直线度（120s 真值）

诱饵全部 0.84~0.99（接近直线，Start→End 单段），但真目标 10001 也 0.98、
10002 仅 0.42。**120s 窗口内不可分**，暂不作为判别信号（留待长窗口特征）。

## 判别设计（合法信息：detection 位置序列 + comm + 代码内置先验）

### 信号优先级

1. **速度硬判（主信号）**：OLS/CvFilter 速度 ≥6.5 且 <14.5 → 判真，进 TRACK。
   覆盖 9/12 m/s 档（96~98%）。上限从 13.5 放宽到 14.5（12 m/s 档 P90 修复）。
2. **5 m/s 存疑档（不再判否）**：
   - OLS 读数 <6.5 或 >14.5 的目标**不记否决冷却**，改短冷却（5s）后重试；
   - 同一候选**二次独立 12s 窗口** OLS 都入带 → 判真（误报 2.5%）。
   - 存疑目标不进 TRACK，不 announce（避免全队聚堆）。
3. **Start 池辅助（否决/倾向）**：离线烘焙 26 真 + 18 诱 Start 进代码：
   - 检测位置距某诱饵 Start <80m 且距最近真 Start >200m → 判诱（否决，保持冷却）；
   - 距某真 Start <80m 且距最近诱 Start >200m → 真倾向（5 m/s 真目标靠此救回，
     与速度判否结合：倾向真 + 速度存疑 → 保持存疑而非否决）；
   - 两池都近（<200m）或都不近 → 存疑。
4. **多机共识（协同兜底）**：comm 广播"候选目标位置+速度估计+判别结论"，
   同一目标两架独立判真 → 强真（消息 ≤50B，4Hz 限制内）。已摧毁记忆保留。

### 状态机改动（agent.py）

- VERIFY：OLS 入带 [6.5, 14.5] → TRACK（不变）；带外 → Start 池判定：
  判诱 → `_mark_reject`（否决冷却）；判真倾向或存疑 → 短冷却回 SEARCH
  （不记否决），二次机会由"同一位置重新 VERIFY"自然获得。
- TRACK 僚机后台 bailout：原 `速度 <5.5 持续 15s → 退出` 会误杀 5 m/s 真目标；
  收紧为 `速度 <4.0 持续 15s 且 Start 池判诱 → 退出`。
- TRACK 长机超时 `_TRACK_TIMEOUT_S=90`：5 m/s 真目标需要僚机汇聚，90s 保留。

### accuracy 保障

- 只 report 已判真目标（存疑不报，防 RMSE 恶化）；
- 三机覆盖：搜索分配保持分扇区，避免全队同区；
- 已摧毁记忆 + 上报"尸体"丢弃规则（手册 §5.2）维持。

## 验收标准

1. 单测（TDD）：判别逻辑覆盖——5 m/s 二次验证判真、诱饵 Start 否决、
   9/12 判真、上限 14.5、bailout 收紧、存疑不记否决。
2. 跑局：600s × 3 局，kill>0 且至少 2 局有击杀；accuracy>0；proximity ≤5；
   pytest 全过。

## 风险

- 验证阶段真目标换新路线（手册 §5）：Start 池烘焙失效 → 速度硬判仍兜底
  （9/12 档不受影响）；5 m/s 真目标在验证集靠"二次验证 + 不否决"兜底。
- 二次验证引入 ~12s 判别延迟：协同汇聚预算内（90s 超时）。
