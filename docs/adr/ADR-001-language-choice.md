# ADR-001: 核心算法语言选择（Python vs Rust）

## 状态

**已决** — Rust 用于计算密集型服务，Python 作为集成层

## 背景

参赛者希望用 Rust 实现核心算法以获得更好的性能。平台 SDK 要求"仅允许单模块 Agent 文件，继承对应赛道基类"，同时允许提交"算法依赖文件"。

## 决策点

### 选项 A：纯 Python

- 所有算法在 Python 中实现
- 最符合提交要求，零集成风险
- 10Hz 决策循环下 Python 性能够用（基线算法全部纯 Python）

### 选项 B：Rust 核心 + Python 薄壳

- 用 PyO3/Maturin 编译 Rust 为 Python 扩展（.pyd/.so）
- Python Agent 的 `decide()` 中调用 Rust 函数
- 需要确认组委会是否接受编译产物作为"依赖文件"

### 选项 C：Python 在线 + Rust 离线

- Python 实现在线决策（decide 循环）
- Rust 用于离线训练/仿真/参数优化
- 零提交风险，但 Rust 价值有限

## 各选项分析

| 维度 | A: 纯 Python | B: Rust+Python | C: Python在线+Rust离线 |
|---|---|---|---|
| 性能 | 够用（10Hz，基线验证） | 最优 | 在线同A，离线最优 |
| 提交风险 | 无 | 高（编译产物是否被接受？） | 无 |
| 开发复杂度 | 低 | 高（PyO3 构建链） | 中（两套代码） |
| 调试难度 | 低 | 高（跨语言调试） | 中 |
| 创新点 | 无语言层面的 | 有（高性能算法） | 有（训练框架） |

## 关键约束

1. 赛题一（单机）：10Hz 循环 + 简单逻辑 → Python 完全够用
2. 赛题二（3机协同）：滤波 + 速度估计 + 通信协议 → Python 仍够用
3. 赛题三（10机对抗）：路径规划 + K=3 分配 + 威胁规避 + 滤波 → 计算量更大，但仍可在 100ms 内完成

## 影响

此决策影响：项目构建链、技术报告的创新点论述、代码结构。

## 决策

**选项 B：Rust 核心 + Python 集成层**，采用多文件打包方式提交。

Rust 负责计算密集型服务（具体算法待文献调研后决定）：
- 滤波器
- 路径规划
- 任务分配算法
- 几何计算

Python 负责：
- Agent 入口（decide 回调）
- 通信协议编解码
- 状态机逻辑
- 调用 Rust 计算服务

构建方式：PyO3 + Maturin，编译为 Python 可 import 的 .pyd/.so。
