# ADR-002: 赛道选择策略

## 状态

**已决** — 基于赛题三设计框架，自底向上实现：赛题一 → 赛题二 → 赛题三

## 背景

三条赛道难度梯度明显，参赛者需选择赛道。技术报告和算法代码都需要针对特定赛道提交。

## 决策点

### 选项 A：专攻一条赛道

- 集中精力拿到该赛道最高分
- 报告深度足够
- 风险：选错赛道可能浪费时间

### 选项 B：三条赛道全覆盖

- 展示全面能力
- 但每条赛道深度不足，可能都达不到高分
- 工作量极大

### 选项 C：主攻一条 + 附带一条

- 主赛道深度优化，附带赛道达标即可
- 技术报告可以有对比分析
- 适中的工作量

## 各赛道技术挑战

### 赛题一：单机搜索跟踪

- 核心挑战：区域遍历搜索 + 云台稳定跟踪 + 位置估计
- 关键技术：EMA 滤波、阿基米德螺旋搜索、LOS 瞄准、前瞻补偿
- 评分：精度 100%（全程 1Hz 上报，每 20s 去 2 最低）
- 基线参考：search_track_fsm（有限状态机，已能达标）

### 赛题二：多机协同识别

- 核心挑战：诱饵鉴别（15 个静止 vs 3 个运动）+ K=2 协同盯防
- 关键技术：运动学判别（回归速度/位置散布）、通信协议、任务分配
- 评分：摧毁 50% + 精度 30% + 用时 20%
- 基线参考：coop_distributed（分布式分区，但 K=1 实际无协同）

### 赛题三：对抗集群搜索

- 核心挑战：K=3 分布式协同 + SAM 规避 + 干扰区感知 + 10 目标管理
- 关键技术：网格分配、扇区环协同、威胁区高度规避、动态干扰广播
- 评分：摧毁 40% + 用时 25% + 精度 25% + 存活 10%
- 基线参考：swarm_coordinated（最复杂，已有 K=3 协同框架）

## 影响

赛道选择决定算法复杂度、技术报告方向、开发周期分配。
